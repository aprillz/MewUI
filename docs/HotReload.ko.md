# Hot Reload

이 문서는 MewUI C# 마크업 앱의 **Hot Reload** 동작을 설명합니다. 코드를 편집하면
`dotnet watch`(또는 IDE의 Hot Reload)가 실행 중인 앱에 변경을 적용하고, MewUI는 **바뀐
빌드 코드에 해당하는 노드만** 다시 빌드합니다.

Hot Reload는 디버그(JIT) 세션에서만 동작합니다. 릴리스/NativeAOT 빌드에서는 완전히
비활성화됩니다.

---

## 1. 활성화 (설정 불필요)

MewUI가 Hot Reload 핸들러를 자체 어셈블리에 등록하므로 **앱에 별도 선언이 필요 없습니다.**
`dotnet watch`로 실행하면 바로 동작합니다.

```
dotnet watch run
```

> 이전 버전에서 쓰던 `#if DEBUG [assembly: MetadataUpdateHandler(...)]` 수동 선언은 더 이상
> 필요 없습니다. 남아 있으면 중복 등록이 되므로 제거하세요.

### 끄기 (opt-out)

프로젝트에서 다음 속성으로 Hot Reload를 비활성화할 수 있습니다.

```xml
<PropertyGroup>
  <MewUIHotReload>false</MewUIHotReload>
</PropertyGroup>
```

---

## 2. 편집 종류별 반영과 동작 방식

무엇을 편집하느냐에 따라 **다시 빌드하는 범위**와 **유지되는 상태**가 달라집니다.

| 편집한 것 | 화면 반영 | 다시 빌드하는 범위 | 유지되는 상태 |
| --- | --- | --- | --- |
| Window `.Build(...)`/`OnBuild()` / UserControl `OnBuild()` 본문 | 저장 즉시 | 그 창/컨트롤 하나 | 그 노드 **바깥**(형제·다른 창) |
| 빌드가 실행하는 코드: 앱 안 어느 타입의 헬퍼 메서드든, 빌드가 만드는 컨트롤의 생성자, 빌드가 호출하는 재정의 | 저장 즉시 | 그 코드를 실행하는 빌드의 창/컨트롤 전부 | 그 노드들 바깥 |
| 이벤트 핸들러 `.OnClick(...)`, `+=` 등의 본문과 핸들러만 실행하는 코드(예: 핸들러가 부르는 뷰모델 메서드) | 다음 이벤트부터 | **없음** | **전부** 유지 |
| 사용자 정의 컨트롤의 렌더링·레이아웃·입력 재정의(`MeasureOverride`, `OnRender` 등) | 저장 즉시 | 없음: 그 컨트롤의 살아 있는 인스턴스를 다시 측정하고 다시 그림 | **전부** 유지 |
| 아이템 템플릿 `ItemTemplate` 등의 빌드 함수 | 저장 즉시 | 그 템플릿을 설정하는 빌드의 창/컨트롤 | 그 노드 바깥 |
| 그 밖의 앱 코드(UI에서 아무도 호출하지 않는 메서드, 시작 코드만 쓰는 클래스 등) | 저장 즉시 | 등록된 빌드 **전부** | 다시 빌드한 노드 바깥 |
| 기본 스타일 정의 | 다음 재빌드 때 | (재빌드에 편승) | — |
| 시그니처·구조 변경 (rude edit) | 앱 재시작 후 | 전체 | 없음 |

### 왜 이렇게 되나

**1) 변경 감지는 빌드가 실행하는 코드를 따라갑니다.**

런타임은 "어떤 타입이 바뀌었는지"만 알려주고, C# 마크업에서는 빌드 코드와 이벤트 핸들러가 보통 같은 타입에 함께 있습니다. 그래서 MewUI는 등록된 빌드 함수마다 그 빌드가 실행하는 메서드를 기록합니다. 호출하는 메서드, 생성하는 객체의 생성자, 호출이 디스패치되는 재정의, 빌드 중에 실행하는 람다를 앱의 디버그 빌드 어셈블리 안에서 따라갑니다. 빌드가 구독한 이벤트 핸들러가 실행하는 코드도 같은 방식으로 기록하고, 둘 중 하나가 닿은 타입의 나머지 메서드도 모두 기준선을 남깁니다. 변경이 들어올 때마다 이 메서드들의 본문을 비교하고(메타데이터 토큰 재배치 같은 컴파일러 잡음은 무시), 바뀐 메서드를 실행하는 빌드의 노드를 다시 빌드합니다.

**2) 핸들러 편집은 재빌드가 필요 없습니다.**

이벤트 구독(`OnXxx(...)` 마크업 메서드나 `+=`)에 넘긴 람다나 메서드, 그리고 그것이 호출하는 코드는 빌드가 실행하지 않습니다. .NET은 메서드 본문을 제자리에서 교체하고, 빌드 시점에 연결된 델리게이트는 그대로 남아 다음 이벤트에서 새 본문이 실행됩니다. 창을 다시 만들지 않으므로 입력 중인 값·스크롤·선택 같은 상태가 유지됩니다.

**3) 프레임워크 콜백은 다시 그리기만 하면 됩니다.**

`MeasureOverride`나 `OnRender`처럼 프레임워크가 살아 있는 컨트롤에 호출하는 재정의는, 다음에 호출될 때 이미 새 본문으로 실행됩니다. MewUI는 그 컨트롤의 살아 있는 인스턴스의 측정과 렌더링을 무효화해 그 호출이 바로 일어나게 하고, 아무것도 다시 빌드하지 않습니다.

**4) 추적할 수 없는 변경은 빌드를 전부 다시 실행합니다.**

등록된 빌드도 핸들러도 실행하지 않는 메서드(리플렉션이나 나중을 위해 저장한 델리게이트로만 닿는 코드, 아무도 호출하지 않는 메서드, 시작 코드만 쓰는 클래스)가 바뀌어도 화면에 영향을 줄 수 있지만, MewUI는 그 위치를 알 수 없습니다. 이 경우 Blazor와 Flutter가 모든 변경에 하듯 등록된 빌드를 전부 다시 실행하고, 어떤 변경 때문인지 콘솔에 출력합니다. 변경으로 새로 추가된 타입은 이 경우에 해당하지 않습니다. 전에는 아무도 실행하지 않았고, 그 타입을 부르는 편집된 코드가 따로 감지되기 때문입니다.

**5) 영향받은 가장 얕은 노드만 다시 빌드합니다.**

영향받은 노드가 여럿이면, 조상 노드를 다시 빌드할 때 그 자식들이 새로 생성되므로 조상만 다시 빌드합니다. 영향받지 않은 부분과 다른 창은 그대로 둡니다.

이 원리에서 다음 한계도 따라옵니다.

- 이벤트 구독이 아닌 곳에 넘긴 델리게이트는 빌드 코드로 봅니다. 그런 델리게이트(예: 바인딩 변환 함수)를 고치면 델리게이트가 나중에 실행되더라도 그것을 만드는 노드가 다시 빌드됩니다.
- 릴리스로 빌드된 라이브러리의 코드는 추적하지 않습니다.
- 생성자에서 내용을 만드는 컨트롤은 그 컨트롤을 생성하는 창/컨트롤의 빌드를 다시 실행해 갱신합니다. `Main`에서 바로 만든 창(`new Window().Content(...)`)은 다시 실행할 빌드가 없으므로 `.Build(...)` 콜백이나 `OnBuild()` 재정의를 쓰세요.
- 시그니처·베이스 타입·구조 변경 등은 런타임이 변경 델타를 애초에 적용하지 못해(rude edit) 재시작이 필요합니다.

## 3. 빌드 코드 등록

Hot Reload가 다시 빌드하는 대상은 빌드 함수가 등록된 노드입니다. 다음이 자동으로
등록됩니다.

- **Window의 `.Build(...)`**: 콜백을 등록하고 초기 빌드도 실행합니다.
- **Window의 `OnBuild()` override**: 첫 표시 직전에 실행되며 그때 등록됩니다.
- **UserControl의 `OnBuild()` override**: 컨트롤이 콘텐츠를 빌드할 때 등록됩니다.

### 빌드 소유권

창의 빌드는 정확히 한 곳이 소유합니다: **`Build(...)` 콜백이 설정되어 있으면 콜백, 없으면 가상 `OnBuild()`.** 콜백이 있는 창에서는 가상 후크가 호출되지 않으며, `OnBuild()`를 오버라이드한 창에 콜백을 붙이면 디버그 빌드에서 예외로 알려줍니다. 재빌드도 항상 현재 소유자 하나만 재실행됩니다.

관용구 선택 기준: 명명된 재사용 창(다이얼로그 등)은 `OnBuild()` 오버라이드, 조합 지점의 일회성 창(Main의 메인 창 등)은 fluent `Build(...)`가 맞습니다.

### 재실행 가능성 규칙

빌드 코드(콜백/오버라이드 공통)는 Hot Reload와 에디터 프리뷰가 **반복 재실행**합니다. 따라서 재실행 가능한 구성만 담아야 합니다:

- 표시 후 변경 불가인 창 스펙(`StartupLocation` 등)은 재빌드에서 예외를 냅니다.
- 이벤트 구독(`OnClosed(...)` 등)은 재실행마다 중복 등록됩니다.

1회성 스펙과 구독은 생성자나 조합 지점 체인(빌드 콜백 바깥)에 두세요.

```csharp
public class AboutDialog : Window
{
    public AboutDialog()
    {
        // 1회성: 창 스펙과 이벤트 구독
        this.Fixed(400, 340).StartCenterOwner().OnClosed(SaveState);
    }

    protected override void OnBuild()
    {
        // 재실행 가능: 언제 다시 실행돼도 같은 결과
        this.Title("About").Padding(new Thickness(20)).Content(BuildUI());
    }
}
```

```csharp
var window = new Window()
    .Build(w => w
        .Title("Hot Reload Demo")
        .Content(new StackPanel()
            .Spacing(8)
            .Children(
                new TextBlock().Text("코드를 수정하고 저장하세요."),
                new Button()
                    .Content("Click")
                    .OnClick(() => Console.WriteLine("clicked"))   // 이 본문 편집 → 재빌드 없음
            )));
```

위에서 `TextBlock`의 텍스트를 바꾸면 창이 다시 빌드되고, `OnClick` 본문을 바꾸면 재빌드
없이 다음 클릭부터 새 동작이 적용됩니다.

## 4. 전체 예시

```csharp
using Aprillz.MewUI;
using Aprillz.MewUI.Markup;
using Aprillz.MewUI.Controls;

var window = new Window()
    .Build(w => w
        .Title("Hot Reload Demo")
        .Content(new StackPanel()
            .Spacing(8)
            .Children(
                new TextBlock().Text($"Now: {DateTime.Now}"),
                new Button().Content("Click")
            )));

Application.Create()
    .UseWin32()
    .UseDirect2D()
    .Run(window);
```

`dotnet watch run`으로 실행한 뒤 `TextBlock` 텍스트를 편집하면 변경이 즉시 반영됩니다.

## 5. 참고 사항

- **다시 빌드된 노드 내부의 상태는 초기화됩니다.** 유지해야 하는 상태는 빌드 함수 밖의
  ViewModel/서비스에 두세요. (핸들러 편집은 재빌드가 없으므로 상태가 보존됩니다.)
- Hot Reload는 디버그(JIT)에서만 동작하며, 릴리스·NativeAOT에서는 아무 동작도 하지 않습니다.
- 앱이 실행되기 전에 도착한 변경은 다시 빌드할 필요가 없습니다. 창이 편집된 코드로 빌드됩니다.
- 변경을 적용할 때마다 콘솔 오류 스트림에 `[MewUI HotReload]` 줄이 출력됩니다. 바뀐 메서드 수, 다시 빌드한 노드 수, 다시 그린 요소 수, 핸들러 전용 변경 수가 담기고, 빌드를 전부 다시 실행했으면 그 이유도 담깁니다. 다시 빌드하다 예외가 나면 그것도 여기에 출력됩니다. 나머지 노드는 계속 다시 빌드되고, 실패한 노드는 이전 내용을 유지한 채 다음 변경 때 다시 시도됩니다.
